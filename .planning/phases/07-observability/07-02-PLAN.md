### MDC in SLF4J
`org.slf4j.MDC` is already available (SLF4J API is on the classpath).
`MDC.put(key, value)` sets a value; `MDC.remove(key)` removes one; `MDC.clear()` removes all.
MDC is thread-local — must be set and cleared on the same thread.

### MDC keys to populate

**WorkflowThread** (in `run()`):
- `"workflowId"` = `context.workflowId`
- `"workflowType"` = `context.workflowType`
- Clear both in `finally`

**ActivityDispatcher** (in `executeActivity()`, before the retry loop):
- `"activityId"` = `scheduled.activityId()`
- `"activityType"` = `scheduled.activityType()`
- Clear both in the `finally` block around the retry loop (same finally that decrements `pendingActivities`)

### Testing metrics with SimpleMeterRegistry

```java
import io.micrometer.core.instrument.simple.SimpleMeterRegistry;

SimpleMeterRegistry registry = new SimpleMeterRegistry();
Worker worker = Worker.newBuilder()
    .taskQueue("test")
    .sharedLog(sharedLog)
    .metricsRegistry(registry)  // inject test registry
    .build();
// ... run workflow or activity ...
// Assert via registry.counter(...).count() or registry.timer(...).count()
double count = registry.counter("boudin.workflow.completed", "workflowType", "GreetingWorkflow").count();
assertThat(count).isEqualTo(1.0);
```

For timers:
```java
long timerCount = registry.timer("boudin.workflow.duration", "workflowType", "GreetingWorkflow").count();
assertThat(timerCount).isEqualTo(1L);
```

For gauges, note they reflect the current state — they're 0 after the workflow finishes:
```java
double pending = registry.get("boudin.worker.pending_workflows")
    .tag("taskQueue", "test").gauge().value();
assertThat(pending).isEqualTo(0.0);
```

### workflowType name derivation
The workflowType stored in history (and used as the metrics tag) is the simple name of the
`@WorkflowInterface`-annotated interface — e.g., `"GreetingWorkflow"` for an interface
called `GreetingWorkflow`.

### activityType format
`activityType` in `ActivityScheduled` is `"InterfaceName#methodName"` (set by `ActivityStub`).
Use the full string as the tag value in metrics.

```java
// Re-use GreetingWorkflow / GreetingWorkflowImpl from prior tests — define as inner classes

@WorkflowInterface
public interface GreetingWorkflow {
    @WorkflowMethod
    String greet(String name);
}

public static class GreetingWorkflowImpl implements GreetingWorkflow {
    @Override
    public String greet(String name) { return "Hello, " + name + "!"; }
}

@ActivityInterface
public interface EchoActivities {
    @ActivityMethod
    String echo(String input);
}

public static class EchoActivitiesImpl implements EchoActivities {
    @Override
    public String echo(String input) { return input; }
}

@WorkflowInterface
public interface EchoWorkflow {
    @WorkflowMethod
    String run(String input);
}

public static class EchoWorkflowImpl implements EchoWorkflow {
    private final EchoActivities activities = Workflow.newActivityStub(EchoActivities.class);
    @Override
    public String run(String input) { return activities.echo(input); }
}

@WorkflowInterface
public interface FailingWorkflow {
    @WorkflowMethod
    void run();
}

public static class FailingWorkflowImpl implements FailingWorkflow {
    @Override
    public void run() { throw new RuntimeException("boom"); }
}
```

**Test 3** — `activityCompletedCounterIsIncremented()`:

- Assert `boudin.activity.duration` timer count == 1
- Assert `boudin.activity.retries` count == 0

**Test 4** — `pendingWorkflowsGaugeReturnsToZeroAfterCompletion()`:
- Inject `SimpleMeterRegistry`
- Run `GreetingWorkflowImpl` to completion
- After completion, get the gauge value for `"boudin.worker.pending_workflows"` with tag `taskQueue="test"`
- Assert it is 0.0 (workflow finished, removed from pending)

Note on counter assertions: use `registry.counter("name", "tag", "value").count()` which returns 0.0
if the counter was never touched (Micrometer returns the counter with 0 count for unregistered meters
via `SimpleMeterRegistry`). For workflow failed with 0 expected, use:
```java
// Check if meter exists, default to 0 if not
double failedCount = registry.getMeters().stream()
    .filter(m -> m.getId().getName().equals("boudin.workflow.failed"))
    .mapToDouble(m -> ((Counter) m).count())
    .sum();
assertThat(failedCount).isEqualTo(0.0);
```
Or simpler: since `SimpleMeterRegistry` creates meters on first access, calling
`registry.counter("boudin.workflow.failed", "workflowType", "GreetingWorkflow").count()`
will return 0.0 even if no failure was recorded (meter is lazily initialized to 0).
