# Phase 1, Plan 1: Foundation & Correctness

## Objective

Fix five correctness bugs in the current codebase before building anything new:
signal delivery idempotency, pending activity memory leak, silent activity registration failure,
duplicate WorkflowMethod detection, and fragile Thread.sleep() in tests.

## Context

The existing codebase has these specific correctness issues identified during codebase analysis:

1. **Signal delivery not idempotent** — `WorkflowRunner.onHistoryEvent()` has no deduplication. If a subscription delivers the same `SignalReceived` event twice, the signal handler fires twice. Fix: track processed event seqnums.

2. **Pending activities never pruned** — `WorkflowContext.pendingActivities` is a `ConcurrentHashMap` that accumulates completed futures forever. `awaitActivityResult()` adds entries on demand; neither `deliverActivityResult` nor `deliverActivityFailure` removes them after use. Fix: remove in `awaitActivityResult` after `future.join()` returns.

3. **Silent activity registration failure** — `ActivityRegistry.register()` silently does nothing if the passed object implements no `@ActivityInterface`-annotated interface. Users register the wrong class and get runtime errors much later. Fix: throw immediately.

4. **Multiple `@WorkflowMethod` not detected** — `WorkflowRegistry.findAnnotatedMethod()` returns the first match; if a workflow interface has two `@WorkflowMethod`-annotated methods, the second is silently ignored. Fix: count and throw if > 1.

5. **Fragile Thread.sleep(200) in tests** — `workflowWithSignalBeforeRun` uses a 200ms sleep to wait for the workflow to reach `Workflow.await()`. This is fragile on slow CI. Fix: add an `AtomicBoolean` signal point to `WaitingWorkflowImpl` and use Awaitility.

### Task 2 — Prune completed activity futures in WorkflowContext

**File:** `src/main/java/com/cajunsystems/boudin/workflow/WorkflowContext.java`

In `awaitActivityResult()`, wrap the join in try-finally:
```java
public byte[] awaitActivityResult(String activityId) {
    CompletableFuture<byte[]> future =
            pendingActivities.computeIfAbsent(activityId, id -> new CompletableFuture<>());
    try {
        return future.join();
    } finally {
        pendingActivities.remove(activityId);
    }
}
```

No other changes to this method — the `computeIfAbsent` race-condition handling is correct and must be preserved.

```java
public void register(Object activityImpl) {
    Class<?> implClass = activityImpl.getClass();
    boolean foundInterface = false;
    for (Class<?> iface : implClass.getInterfaces()) {
        if (!iface.isAnnotationPresent(ActivityInterface.class)) continue;
        foundInterface = true;
        for (Method method : iface.getDeclaredMethods()) {

        }
    }

        throw new IllegalArgumentException(
                implClass.getName() + " does not implement any @ActivityInterface-annotated interface");
    }
}
```

Replace `findAnnotatedMethod` with:
```java
private static Method findAnnotatedMethod(Class<?> iface,
        Class<? extends java.lang.annotation.Annotation> annotationClass) {
    List<Method> matches = Arrays.stream(iface.getDeclaredMethods())
            .filter(m -> m.isAnnotationPresent(annotationClass))
            .toList();
    if (matches.isEmpty()) {
        throw new IllegalArgumentException(
                iface.getName() + " has no @" + annotationClass.getSimpleName() + "-annotated method");
    }
    if (matches.size() > 1) {
        throw new IllegalArgumentException(
                iface.getName() + " has " + matches.size() + " @" +
                annotationClass.getSimpleName() + "-annotated methods; exactly one is required. " +
                "Found: " + matches.stream().map(Method::getName).toList());
    }
    return matches.getFirst();
}
```
Add import: `java.util.Arrays`, `java.util.List`
