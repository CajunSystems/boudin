# Phase 3, Plan 2: Route WorkflowRunner History Events Through Event Loop

## Objective

Route `WorkflowRunner`'s history subscription callbacks through the `BoudinEventLoop`
so that all per-workflow event delivery (activity results, signals, timer fires) flows
through one serialized thread. This makes Phase 4 timer integration trivially safe and
eliminates the last inline-callback dependency on Gumbo's notification threads.

## Execution Context

Read these files before starting:
- `src/main/java/com/cajunsystems/boudin/internal/WorkflowRunner.java`
- `src/main/java/com/cajunsystems/boudin/internal/WorkflowDispatcher.java`
- `src/main/java/com/cajunsystems/boudin/api/Worker.java`

## Context

**Current flow:** Gumbo notification thread → `WorkflowRunner.onHistoryEvent()` inline

**After this plan:** Gumbo notification thread → `eventLoop.submit(onHistoryEvent)` → event loop thread

`onHistoryEvent()` is lightweight — it completes CompletableFutures and invokes signal
methods (which call `notifyAll()`). No blocking I/O. Perfect for the event loop thread.

**Why this matters for Phase 4:**
`Workflow.sleep()` will append `TimerStarted` to history, schedule a timer on `HashedWheelTimer`,
and park the workflow virtual thread. When the timer fires (on the event loop), it appends
`TimerFired` to the workflow history. The history subscription picks that up and calls
`onHistoryEvent` — which, routed through the event loop, runs on the same thread as the
timer callback. This makes the delivery guarantee clean: timer fires → event submitted
to loop → delivered to workflow context → workflow unparks.

**Dispatcher live subscriptions (WorkflowDispatcher, ActivityDispatcher):**
These remain on Gumbo notification threads for now. Their callbacks are infrequent
and primarily spawn virtual threads for blocking work. Routing them through the event
loop is deferred to when it adds concrete value (Phase 5).

**Constructor chain:**
- `Worker` (already has eventLoop from Plan 03-01) passes it to `WorkflowDispatcher`
- `WorkflowDispatcher` passes it to each `WorkflowRunner` it creates
- `WorkflowRunner` uses it in the subscription lambda

### Task 2 — Add eventLoop to WorkflowRunner and route subscription

**File:** `src/main/java/com/cajunsystems/boudin/internal/WorkflowRunner.java`

Add import:
```java
import com.cajunsystems.boudin.internal.BoudinEventLoop;
```

Add field after `onComplete`:
```java
private final BoudinEventLoop eventLoop;
```

Update constructor (8th parameter):
```java
public WorkflowRunner(String workflowId,
                      String taskQueue,
                      SharedLog sharedLog,
                      WorkflowRegistry workflowRegistry,
                      List<HistoryEvent> existingHistory,
                      long lastHistorySeqnum,
                      Runnable onComplete,
                      BoudinEventLoop eventLoop) {
    this.workflowId = workflowId;
    this.taskQueue = taskQueue;
    this.sharedLog = sharedLog;
    this.workflowRegistry = workflowRegistry;
    this.existingHistory = existingHistory;
    this.lastHistorySeqnum = lastHistorySeqnum;
    this.onComplete = onComplete;
    this.eventLoop = eventLoop;
}
```

In `start()`, **replace** the `historySubscription = historyView.subscribe(...)` block:
```java
historySubscription = historyView.subscribe(
        new LogPosition(subscribeFrom),
        entry -> {
            long seqnum = entry.seqnum();
            HistoryEvent event = HistorySerializer.INSTANCE.deserialize(entry.data());
            eventLoop.submit(() -> onHistoryEvent(seqnum, event, impl, workflowType));
        }
);
```
